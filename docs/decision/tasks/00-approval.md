# G0 — Аппрув и подготовка диспетча

**Ответственный:** tl. **Приоритет:** P1 после GO в очереди этого эпика. **Зависимости:** нет.
**Срок:** до первого исполнительного листа; 30–60 минут после явного GO; первая контрольная точка ≤90 минут после выдачи, если timebox короче — сдача в его пределах. Календарный срок назначает tl при диспетче.

**Разрешения и факт выдачи — только в [PROGRESS.md](PROGRESS.md); сам файл не является диспетчем.** Полный clean-slate контекст: [SPEC v0.2](../SPEC.md), [контекст](_shared/context.md), [швы](_shared/interfaces.md), [приёмка](_shared/acceptance.md), [состояние/аппрув](PROGRESS.md), [baseline](baseline.json).

## Цель и scope
Получить явный аппрув владельца на конкретные baseline/spec/tree и scope GO-IMPLEMENT. Наличие дерева — не разрешение. Приоритет P1 в очереди эпика; фактическое место среди текущих работ фиксирует tl после GO.

## Действия после аппрува
Записать подтверждение в PROGRESS без секретов; re-resolve main/bytes, проверить доступность dev/test и их текущий WIP, обеспечить isolated worktrees и последовательность. Дать dev только D01, затем test Q00 после D01. Контракты _shared/interfaces.md принимаются вместе с планом; новое неразрешённое изменение — обратно владельцу через tl.

## DoD
G0 PASS означает документированное явное GO-IMPLEMENT, согласованный scope park main, актуальный baseline и аллокацию. Актуальное разрешение и аллокация фиксируются в PROGRESS.md. Не запускать/не будить/не чистить роли и не выдавать листы до GO. В аппруве полного дерева должны быть понятны scope park main и до трёх платных POST Q02; при одобрении только локальной части Q02 остаётся HOLD. GO-RELEASE не подразумевается.

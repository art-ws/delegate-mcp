# Общий контекст исполнения

**Сначала прочитать [PROGRESS.md](../PROGRESS.md). До явного аппрува владельца всё исполнение HOLD.** Этот файл и каждый лист — план, не постановка в работу. Подготовка документации не снимает gate.

Канон: [SPEC.md v0.2](../../SPEC.md), [input schema](../../input.schema.json), [output schema](../../output.schema.json). База до реализации и отпечатки — [baseline.json](../baseline.json). До GO не менять эти файлы, src/, test/, package.json, lockfile, CI или реальные конфиги; не создавать исполнительные worktrees, не устанавливать зависимости, не запускать build/tests/MCP/live и не брать реальный ключ. Допустима только подготовка/сохранение этого дерева и его проверка как документа.

## Scope после GO-IMPLEMENT

Один decision в существующем delegate-mcp, Node ≥20, тот же bin/config/stdio process. Полный контракт Jev, optional policy, безопасные ошибки и observability; сохранение analyze/query/resume. Цель этапа — независимо проверенный код в основной ветке существующего проекта и готовый release-кандидат. Никаких новых npm-пакетов/серверов/ролей, UI, БД, изменения модели reader-пула, streaming, caching, автономного выполнения выбранных действий или регистрации сервера агентам.

Явный аппрув **этого полного дерева** разрешает GO-IMPLEMENT: локальную разработку, mock QA, feature-ветку/draft PR, park в main после Q01 через G1 и ограниченный живой smoke Q02 (до трёх платных POST без retries). Если владелец одобрит только локальную часть, Q02 остаётся HOLD до расширения scope. **GO-RELEASE отдельный:** выпуск npm/активация не входят в аппрув реализации. Сохранённый ключ, начало диалога о реализации и прошлые разрешения не снимают текущий HOLD. Если владелец одобрит меньший scope, TL фиксирует его до выдачи первого листа.

## Команда и диспетч

Ровно tl/dev/test. tl — очередь, статусы, чтение evidence, review/интеграция и доклад; dev — реализация; test — независимый план и проверки, включая мутации. Один активный лист на роль. dev идёт D01→D02→D03→D04→D05→D06→D07. test начинает Q00 после D01, может работать одновременно с dev; Q01 после D07 и Q00. Руки не ставят задачи друг другу и не ждут ответов друг друга: вопросы и зависимости решает tl.

Перед каждым новым листом tl проверяет занятость роли, обеспечивает clean-slate и выдаёт один самодостаточный бриф: лист + эти общие файлы + SPEC + точный SHA predecessor. До GO роли не запускаются, не очищаются и не получают задач по этому эпику. Срок каждого листа задан относительным timebox; календарные сроки TL подтверждает при GO и фактической аллокации, без вытеснения текущей чужой работы.

## Источник, ветки и общие ресурсы

После GO работа и проверки — в отдельных worktrees на feature-ветке от зафиксированного SHA; общий checkout не использовать для install/build/test. Плановое имя интеграционной ветки feat/decision-v0.2; сейчас ветка и worktrees не созданы. Коммиты отдельны по листьям, пути только свои. TL при выдаче проверяет свежий main: изменившийся SHA сравнивается с baseline, конфликты канона/входов разрешаются до старта, не молча рукой.

Любая мутация основного checkout — под lockctl delegate-mcp/main-checkout. Локальные mock HTTP серверы используют свободный loopback-порт, принадлежащий одному процессу; без фиксированных общих 1080/8080. Стресс под искусственной общей CPU-нагрузкой не требуется этим деревом. Запрет live на этапах dev/Q00/Q01 обеспечивается injectable transport + fixture endpoints, без настоящего ключа.

## Безопасность и evidence

Публичный проект: ключи, локальные адреса, профили, конфиги доступа, имя/путь реального хранилища команды не попадают в git, отчёты, переписку, argv, stdout/stderr. В проекте только env:OPENROUTER_API_KEY и синтетические canary. Фактический Keychain/ENV launch путь выдаётся test отдельным приватным брифом только для разрешённого Q02; значения не копируются.

Каждый пакет сдачи: leaf ID, source SHA, diff/owned paths, команды и rc, именованные AC PASS/FAIL/NOT_RUN, фактические findings, DEFERRED, secret-safe evidence paths. Пакет содержит restore/повторения из чистого контекста; одна строка «тесты зелёные» не сдача. dev подтверждает компоненты, test — независимую приёмку; tl не проводит runtime QA.

Сначала build того артефакта, который читает проверка, затем тест. Общий локальный gate: npm run build → npm run typecheck → npm run lint → npm test → npm run secretlint. Для leaf допускается focused test плюс полный gate в Q01/D07; весь исходный regression suite обязателен в Q01. Node 20 + текущий поддерживаемый Node проверяются на пакете, без смены заявленного engines.

Любая мутация QA имеет заранее записанное ожидаемое красное утверждение. Сначала успешная сборка mutant, затем RED конкретного oracle, восстановление и повторный GREEN. Build failure, инертная мутация и красный соседний тест не засчитываются. Mutable fixtures и попытки сохраняются с разными именами.

## Порог вмешательства

Если для своего результата требуется менять contract/схемы, src/providers|files|sessions|metrics.ts, CLI cascade, engines, новую зависимость/API surface или workflow выпуска, рука сообщает tl. Пока ждёт — делает независимые fixtures/документы своего листа; для затронутого шва безопасное умолчание = текущая SPEC v0.2, без изменения поведения. Если шов нельзя соблюсти, останавливается только зависимый пункт; исход вне предусмотренной вилки допустим и должен быть назван.

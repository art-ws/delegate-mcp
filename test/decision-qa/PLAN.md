# Q00 — независимый план Q01

Источник всех ожидаемых форм — SPEC v0.2 и канонические `input.schema.json` / `output.schema.json` с D01 входным SHA `e4e68eb7d1f3a76752f3eaa03eccc42bf3749ad5`. Экспорт S1 safe validators имеет discriminated result (`success`, `data` либо фиксированные `code/message`), сохраняет исходный JSON и ничего не нормализует. Поэтому form-valid, semantic-invalid ответ допустим на границе D01; ожидаемый reject/assessment закреплён здесь для D03. Fixtures синтетические. Поля `input` в contract vectors — полные DecisionArgs с `state` и непустыми `questions`; `expected_form_valid` находится рядом с input, не внутри аргументов. Метаданные case (`id`, expected, oracle, fixture setup) всегда вне аргументов. `api_key` — неизвестный аргументный ключ только в отдельном INVALID_ARGUMENT control; он не является key-leak oracle.

## Fixture materialization rules

- `contract-vectors.json`: every `input` is a complete DecisionArgs. The positive primitive/boundary/structured cases contain valid state and questions; each negative changes only its stated boundary while all other required fields stay valid. For generated 255/256-entry criteria, the listed `criteria` object is the exact materialized input (keys `c0`…`c254` / `c0`…`c255`); no hidden base merge is used. `expected_form_valid` is case metadata beside `input`. `V-UNKNOWN-API-KEY-ARG` is only a form-validation control.
- `semantic-vectors.json`: each assessment has complete `prepared_args` and an `assessment_input` naming its exact question, policy, and answer; `expected` supplies status/value/reasons or INVALID_ARGUMENT. `A-POLICY-BAD-ID` changes only the policy map key to an absent question; `A-POLICY-BAD-TYPE` uses the existing `q-choice` ID with a Noul policy.
- Every response case names a full `prepared_request` with all requested IDs/types/criteria and a full response object or exact synthetic HTML transport body. `mutation_recipe` describes the single altered response boundary already represented in `response`; it never asks an adapter to infer extra fields. The valid baseline has required usage counts. The intentionally wrong/missing ID/type/field/value cases expect UPSTREAM_PROTOCOL.
- `R-OUT-OF-RANGE-NONFINITE` uses JSON numeric 1.1 as the materialized out-of-range case. Companion direct-call control must construct `Number.NaN` and `Number.POSITIVE_INFINITY` in memory after parsing valid JSON; JSON text itself cannot encode these values.
- The previous incorrect A-CHOICE-AND-FAIL values are retained under `superseded_attempts` with status `INVALID_EXPECTED_OUTCOME_NOT_COVERAGE`; they are not counted as a passing or failing vector.

## HTTP fixture map

Q01 implements deterministic loopback-only routes with injected fetch/clock; bind a free port and no fixed service port. Minimum named route behavior: `ok-minimal` (id/provider/usage.cost and optional answer metrics omitted; required usage.input_tokens/output_tokens present); `missing-usage` (otherwise valid response with usage removed => UPSTREAM_PROTOCOL); `ok-full`; `http-400`, `401`, `402`, `403`, `404`, `413`, `429`, `500`, `502`, `503`, `524`, `529`; `bad-json`; `oversized-json`; `delay-headers`; `delay-body`; `retry-after`; `network-reset`. Each response is synthetic. Assert exact request count, mapped code, retryable/billing_uncertain, status, attempts, fixed safe message and cleanup. Never connect to OpenRouter in Q00/Q01.

## Mutation controls — expected RED before any mutation

Every Q01 mutant sequence is `npm run build` (candidate) → apply exactly one source mutation → `npm run build` (mutant must compile) → `npm test -- test/decision-qa/independent.test.ts -t '<M# named assertion>'` (must fail for the named assertion) → restore the mutation → `npm run build` → rerun the same focused assertion GREEN → full clean-candidate gate. Preserve both mutant and restore command/evidence under separate attempt names. A compile failure, unrelated failing test or non-red named assertion is INVALID; do not call it mutation coverage.
